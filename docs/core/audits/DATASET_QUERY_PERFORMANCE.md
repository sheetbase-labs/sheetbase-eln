# CORE-02.6 Dataset query performance evidence

Measured 2026-08-14 in the local orb PostgreSQL 18 fixture generated by
`pnpm exec tsx scripts/benchmark-dataset-query.ts`.

## Fixture

- 100,000 stable Dataset rows;
- 10 canonical Schema Version fields (text, decimal, date, category);
- four populated typed values per row (400,000 value rows);
- numeric range filter (`titre >= 900,000,000`), date descending sort and
  200-row window;
- the authenticated `api.query_dataset_rows` RPC, not a privileged raw SQL
  substitute.

## Measured result

| Operation                  |      Result |
| -------------------------- | ----------: |
| Fixture creation + analyse | 14,500.2 ms |
| Query, cold-ish first run  |     79.6 ms |
| Query, run 2               |     67.4 ms |
| Query, run 3               |     65.5 ms |

The filter matched 10,000 rows; the RPC returned 200 rows and the authoritative
`totalCount` of 10,000 without transferring the remaining 9,800 rows.

## Integrity-hardened rerun

After CORE-02 integrity hardening, the same reproducible fixture measured:

| Operation                  |      Result |
| -------------------------- | ----------: |
| Fixture creation + analyse | 20,983.1 ms |
| Query, run 1               |     75.0 ms |
| Query, run 2               |     66.0 ms |
| Query, run 3               |     64.5 ms |

This reconfirms the single-Dataset baseline only. The required 100k/80k
composition join, aggregation, paging, and bulk-update measurements remain
open; this document is not CORE-02.6 completion evidence yet.

## Index rationale

The canonical value table already indexed numeric, category and reference
fields. Migration 0066 adds equivalent `(field_id, date_value)` and
`(field_id, timestamp_value)` indexes for the supported range filters and
sorts. The query first constrains `dataset_rows.dataset_id`, then applies typed
`EXISTS` predicates over stable field IDs; it never exposes generated physical
relation/column names.

These are local-orb baselines, not production SLOs. CORE-02.7 may consume the
bounded API, but production capacity testing remains operational hardening.
