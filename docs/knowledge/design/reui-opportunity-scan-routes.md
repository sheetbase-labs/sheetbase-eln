# Route-surface opportunity scan

A discovery pass over `src/routes/**` for generic UI jobs the app hand-rolls
where the ReUI index (Base UI / `base-nova` build, free tier) ships a component —
plus jobs with several hand-rolled versions that should become one in-house
component whether or not ReUI has an item.

The plan's adoption bar ([`docs/knowledge/design/notebook-editor-and-reui.html`](notebook-editor-and-reui.html)
§4.4) and its exclusions (§4.5, §11.6) still govern a _decision_; ADR-0055 is the
standing decision. This file records what exists, so a decision has evidence
instead of an opinion. **No implementation is proposed here.**

Scope: `src/routes/**` — 185 `.tsx` files, of which 119 are not tests
(≈46,100 lines). Component behaviour is cited only where it explains a route
finding; component-internal hand-rolls are recorded in the closing section as
adjacent evidence, not counted as route findings.

Ranking is by **worth doing and what it buys**, per the owner's revision: cost of
the swap against the behaviour gained, the number of screens reached, and
whether one implementation would replace several. Tier labels from the plan are
not used. Exclusions are held only where an ADR or an explicit owner decision
says so, and are reported as such in the final section.

### Adoption mechanics shared by every row

- The `base-nova` pin is in [`components.json`](../../../components.json); the existing precedent is
  `src/components/reui/sortable.tsx`. Install into a scratch directory, read the item, place files by
  hand under `src/components/reui/**`, and re-point `cn` to `#/lib/utils` (§11.1–11.3).
- The A/B harness is live at `/component-compare`
  ([`src/routes/component-compare.tsx`](../../../src/routes/component-compare.tsx),
  [`src/components/component-compare/harness.tsx`](../../../src/components/component-compare/harness.tsx)),
  with **one registered pair** (`pairs/index.ts` → `pairs/notebook-sortable.tsx`). Each candidate above
  needs a pair file and a row in
  [`docs/knowledge/design/component-comparison-record.md`](component-comparison-record.md).
- ADR-0055 decision 4: one component replaces one component, in the same change, with no parallel
  implementation left behind.

## 7. Limits of this scan

- Line numbers are from the base commit
  `35423ec2b2b498da9773c2c39152ab37d8524fbf` (`35423ec`) and drift as the branch moves.
- The scan reads route files. A job hand-rolled **inside a component** that many
  routes render would appear here only as evidence of duplication (§1-4, §1-5,
  §2-D); a component-internal audit is a separate pass.
- No behaviour was executed: no harness run, no axe run, no browser check. Every
  "materially worse" claim is a reading of the code, and each candidate still
  needs the §4.4 checklist run on hostile fixtures before adoption.
- Candidate order is a judgement about value, and the two closest calls are #1
  vs #2 (reach vs instance count) and the two-step verdict on #3.
