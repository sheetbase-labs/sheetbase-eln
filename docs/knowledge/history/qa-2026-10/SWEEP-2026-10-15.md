# Post-fix sweep — every surface, six frames, both themes

Run on 2026-10-15 against `GWP/roadmap-5-qa` after the audit fixes, the browser-suite
repair and the defects that repair exposed. This is the pass the audit's own §6 said
was missing: frames, themes and interactions, driven rather than read.

Instrument: real Chromium (not the Tern pane, whose sessionless tabs made two earlier
readings wrong), one freshly minted Better Auth session per route — PLAT-03
rate-limits `/api/db` per session at 600 requests/60s and one Home render is 109
requests, so a shared session turns a sweep into 429s.

## Defects this sweep and the browser-suite repair found

- `/inbox` header clipped at phone width (408px document at 390) — `006237b8`
- Opening the Projects Fields/Filter menu unmounted the page (`MenuGroupContext is
missing`); the export menu and two stories had the same shape — `b8d898d9`, with a
  source guard proven to fail on the bad state
- Creating a project left the dialog open over the list — `0861cafd`
- Home stated its pace from the sidebar's snapshot, so it could claim work while every
  read it makes was empty — `eea0c4a9`
- Home's inbox total was the length of a 200-row preview; the shell computed its own
  from rows and, because the shell connects as a superuser, subtracted _other people's_
  acknowledgements. One server-side seen-aware count now serves both — `ced078c0`
- The import map step was missing the reference's Example values and Note columns —
  `eea0c4a9`
- `/experiments` rows opened nothing — `274284fc`

## Zoom reflow, accessibility tree and performance (2026-10-15 follow-up)

Same 28 surfaces, real Chromium, one freshly minted Better Auth session per route, at
1440 (control), 200 % (720 CSS px layout viewport) and 400 % (360). Full evidence:
`/tmp/qa4/result-zoom-a11y.json` (84 frames, per-frame widths, clipped controls, the
accessibility tree per route and the timing/heap readings), with the sweep runner
outputs alongside it in `/tmp/qa4/zoom/`.

Zoom reflow: 0 frames with document overflow, 0 clipped interactive controls, 0 console
errors, 0 failed requests and no 429s after the four defects below were fixed. Four
surfaces failed on a 1440 px window at 400 %, all of them the same shape the `/inbox`
header had at phone width — a row that could not wrap or scroll inside the 312 px
content column a 400 % zoom leaves:

- `/experiments` — document 378 px in a 360 px viewport (18 px overflow); "New
  experiment" ended past the viewport with no ancestor able to scroll to it. The header
  row wraps below `md`.
- `/projects` — the same 18 px, from the phone tab row; "More" ended past the viewport.
  Both the title row and the phone tab row wrap.
- `/analysis` — document 377 px (17 px); the "Drafts" tab ended past the viewport. The
  strip scrolls inside its own region, as the Experiments and Projects strips do.
- `/analysis/new` (studio) — no document overflow, but the data-source `select` ran to
  440 px with its ancestors' `overflow-hidden` clipping it and nothing able to scroll to
  it: `AnalysisStudioHeader` carried `shrink-0`, so its own `flex-wrap` never engaged. It
  shrinks and wraps now.

Accessibility-tree proxy (browser accessibility tree + a synthetic 15-stop Tab walk; an
automated proxy, not a VoiceOver/NVDA session): every interactive node on all 28 routes
has a role and a non-empty accessible name, every route has exactly one `h1`, no heading
level is skipped, and `banner`/`main`/`navigation` are present on every route. Focus
follows DOM order for the first 15 stops everywhere except `/client-portal`, which
exposes only four focusable elements and then wraps to the document start — its stops
are in order. One gap left as a report rather than a change: the members table's
row-actions column has an empty `<th>` (`TableHead>{''}`), an app-wide pattern at five
sites, none of which is an interactive control.
