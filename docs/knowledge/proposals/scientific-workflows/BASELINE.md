## Do not turn these into duplicate features

Measurements, bench readings, curated experiment decisions, protocol training, pipeline editing, client Reports and portal messages already have code. New proposals must state the missing end-to-end semantics rather than recreate their pages.

R4 `UI_PORT_SCREENS.md` contains useful original requirements but is stale as a completion inventory. Its old claims that `/admin`, `/configure` and `/planner` remain, or that measurements/training are absent, conflict with later code and the port progress log. Do not copy them into a new queue unchanged.

The September REUSE-02 failure and old PR/CI states were not rerun or fetched. R5-BASE-01 must classify them using evidence at its execution SHA; they are not asserted to fail today. Likewise, accepted ADR-0045/0047/0048 and later owner decisions override older proposed-status summaries.

## Deferred and rejected directions

- Another visual overhaul: the current programme has already adopted app-3 and v3. Finish workflow gaps within that system.
- Another Pipeline engine, chart model or Sheet version store: canonical equivalents already exist.
- Unlimited imports by lifting constants: leaves memory, atomicity, retry and downstream-analysis limits unresolved.
- General multi-Dataset analysis before explicit source semantics: conflicts with ADR-0041; start with an explicit captured canonical Dataset.
- Live AI as the main programme: source correctness, workflow completion and demonstrated usefulness come first.
- New organisation hierarchy or enterprise administration programme: ADR-0044 and adoption evidence still govern that decision.
- Formal regulated validation pack: accepted control decisions do not waive the named intended-use/inspection gate.
- Broad vendor integrations, offline co-editing or a LIMS/MES expansion: no sufficiently specific next-user need was established in this survey.
