## How this run was driven

Every finding comes from an action performed in a browser against the running app and an outcome observed:
the journey harness (`/tmp/qa2/journey.mjs`) identifies controls by accessible role and name from the live
accessibility tree, asserts the resulting state, and reloads to check that a write persisted. Ordinary
rules applied: a control that does nothing is a defect; a write that reports success but does not land is
worse; a failure the user cannot see is not reported at all.

Two environment conditions shaped the run and are recorded here because they produced false findings that the
fix pass disproved on a clean re-drive:

- **The machine ran out of resources mid-sweep** (load average peaked in the hundreds; the shared headless
  Chromium degraded and several sweepers launched their own browser profiles). Findings taken in that window
  were re-driven on a healthy server during the fix pass; the ones that did not reproduce are recorded as
  `not-a-defect` with the evidence that disproved them.
- **The dev server is a Vite dev server**: the first visit to a route costs 30–60 s of module compilation, and
  a cold graph looks like a stall. Findings of the form "the page never loaded" were re-checked before being
  believed.
