## 1. Executive conclusion

Sheetbase has a **coherent Core engine** and a **usable but incomplete scientist product**. Hardening closed the Core review’s security overlay (H1), in-place ad-hoc → composed engine path (H2), frozen composed-grid render (H3), and legacy write surfaces (H4–H5). It is safe to build on FieldDefinition, Dataset, Definition/Instance, Template versions and REV-002 evidence. Those contracts should not be reopened.

The product does **not** yet match the intended loop in `PRODUCT_DIRECTION.md`:

```text
Create Notebook → add Sheet → paste/link/calculate → promote/reuse → submit/freeze
```

**What a scientist can do today (UI):** open a seeded or template-instantiated experiment; author narrative/checklist/file/protocol/materials/plate/chart blocks; add an **ad-hoc** Sheet (local text grid); embed a **composed** Sheet if a Definition is already pinned; link/create Samples from a composed Sheet; browse Datasets read-only; search records/files; register Samples; instantiate protocol and CORE-06 Notebook Templates; review and sign **already submitted** revisions; amend locked records.

**What exists in PostgreSQL but is not productised:** composition adoption, Definition extract/upgrade/materialise, Dataset create/commit/snapshot outside Sheet write-back, Instance calculations, Template upgrade, **Notebook submit**.

**What is missing as both UI and public API:** a deliberate domain API for Models/Datasets/Sheets/Notebooks; import/export framework; credential management UI; service identity for Core RPCs; chart identity on canonical Datasets.

**Delivery priority uses only `medium` and `low`.** There is no production P0 after hardening, so nothing is queued as `high`.

| Priority         | Work                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| **medium**       | PC-01 canonical Sheet, including blank Notebook + submit enabling slices |
| **low (Ready)**  | API-01 contract/docs in parallel with PC-01                              |
| **low (Queued)** | GOV-01 (`viewer` read-only); PLAT-03 security hardening                  |
| **waiting**      | DATA-01 until PC-01 Sheet interaction exists                             |

**Accepted immediate execution:**

```text
PC-01 [Medium]
    +-- blank Notebook enabling slice
    +-- canonical Sheet experience
    +-- specialist tools demoted from default nav (keep routes)
    `-- submit enabling slice

API-01 [Low]  (parallel; stop at contract boundary)
```

Do not start AUTO. Do not revive SCI-010, scientific tables, or a second Template/Dataset system. Do not broaden specialist tools (Analysis, Planner, Calendar, Storage, Instruments, Plate Designer, Report Builder, Lineage) merely because they still have routes.

## 5. API / developer-platform findings

**Current external contract** (`src/lib/external-token.ts`):

- Tables: `projects`, `folders`, `records`, `blocks`, `record_links`, `revisions`, `record_field_definitions`.
- RPCs: project/record/block/template-instantiate set (`create_project`, `create_record`, `create_record_with_blocks`, block mutations, `instantiate_template`, …).
- Fail-closed for unknown resources. Scientific-table resources denied (`src/lib/external-token.test.ts`).

**Not on the allowlist:** Dataset/Sheet/Notebook Template CORE RPCs, `search`, `change_events`, files.

**Credentials:** hash-at-rest, prefix identification, 5-minute JWT, use-time revocation, exchange rate-limit. Scopes still include `scientific:read|write|schema` (`src/lib/api-credentials.ts`) but `SCIENTIFIC_METADATA` is empty — scopes can be minted and do nothing. **No UI to create/revoke credentials.**

**Docs:** `docs/api/external-api.md` still documents `create_scientific_table` / `sheet_*` CLI. That is false after H4. Treat as a **documentation defect**, not a live second API (calls fail closed).

**Missing vs API-01:** versioned public resources, OpenAPI, SDKs, webhooks, idempotency/error policy as a published contract, pagination helpers, Core domain operations.

**Browser vs API:** the browser is a privileged client of PostgREST. External clients cannot perform the Core scientist workflow. That violates “APIs are first-class product surfaces” until API-01.

**Do not** expose every PostgREST table. **Do** allowlist the same RPCs the UI should use (Sheet/Dataset/Notebook/Template/submit).

## 11. Recommended immediate epics (refined)

### PC-01 — Canonical Sheet Experience (**medium** — first implementation task)

- **Goal:** One spreadsheet-native Sheet spanning ad-hoc and composed states.
- **Depends on:** Core H1–H5 (done). Needs a Notebook to live in — include a **minimal blank-experiment create** if PC-03 has not landed, or land PC-03 submit/create in parallel.
- **Outcome:** Scientist starts a Sheet, pastes/edits, adds governed sources via H2 adoption + bindings, links/creates Records, calculates, extracts/upgrades Definition — without two grid products.
- **Surfaces:** Notebook Sheet block (primary), `/sheets/$instanceId` (deep link).
- **Data/API/security:** Call existing RPCs only; UI gating must not be described as enforcement.
- **Acceptance (focused):**
  - Ad-hoc and composed share one grid stack (Handsontable/SheetbaseGrid).
  - Multi-cell paste/copy; typed editors; calculation columns via existing RPCs.
  - Visible actions: bind/adopt composition, extract Definition, upgrade, materialise (preview/apply + conflict/stale states).
  - Provenance/read-only calculated cells; explicit write-back.
  - No new Sheet abstraction; no scientific-table writes.
- **Risks:** Treating H2 adoption as field promotion; scaling virtualisation; Record model hard-coded to `sample`.
- **Parallel:** API-01 allowlist of the same RPCs; DATA-01 after paste exists.

### PC-03 — Notebook Experience (thin first slice; **medium**, parallel with PC-01)

- **Goal:** Scientist can create a blank experiment and submit it.
- **Depends on:** existing `create_record` / `create_record_with_blocks` and `submit_record_revision`.
- **Acceptance:** Project/home “New experiment” creates `kind=experiment`; Notebook chrome Submit uses digest preview + confirmation; locked banner already works; Reviews then receive the submission.
- **Defer to later PC-03:** print/export package, richer slash UX, amendment from Notebook (amend exists on review workspace).

### PC-02 — Dataset & Record workflows

After PC-01 write-back exists. `/datasets` gains create-from-schema, live edit via `commit_dataset_row_batch`, snapshot/version inspect, export. Records: reagent create; do not invent a second registry.

### PC-04 — Templates
