# DSYS-06.2 — tests/visual/parity.spec.ts that loops over design-states.ts

Step 2 of 3 in [DSYS-06](../../tasks/DSYS.md#dsys-06--visual-parity-suite); the full step text is under “Steps” there.

## Work Log
  - 2026-10-10: SampleDetail diagnosed (0.03) and a systematic parity issue identified. The app renders the sample with the real clock while the design is frozen at DESIGN_CLOCK (25 Sep 2026), so the sample's hold state has drifted: the design shows 'Released', the app shows 'Hold exceeded' with 'Hold limit passed on 4 Oct 2026' and Recent history entries dated 10 Oct, because src/lib/sample-hold.server.ts compares the hold deadline to the current time and the scheduled system process has already flipped the sample. DESIGN_CLOCK is documented in tests/visual/parity.spec.ts as a display-data baseline only - it pins seeded dates, not the app's notion of now - and the hold computation is server-side, so a browser clock override would not reach it. Every time-dependent board (hold meters, expiry windows, relative dates) therefore drifts as real time passes, which is also why their diffs move between runs. Fixing it needs a clock seam the server honours (a dev/test-only override in the same spirit as SHEETBASE_DEV_AUTH_FREE) set to DESIGN_CLOCK by the parity suite, or an owner decision to accept measured drift on those boards. Beyond that, SampleDetail's content is largely present: header, tabs (Lineage 11 / Usage 3 / Measurements 0 / History), Properties, Withdrawals and Derived samples all render, and the remaining differences are the status vocabulary and the properties the design lists (Capsid titre, Cell line, Produced in, Harvested).

Still open on this board: the status vocabulary (Stored, Released, Awaiting measurement against available/reserved/frozen/quarantined/expired/hold_exceeded/consumed/disposed). The design's own screens reference different subsets of the same registry - SamplesList lists SMP-2201/2210/2214/2220/2227/2231/2236/2238/2248/2249/2250, while SampleDetail, SampleLineage and SampleUsage reference SMP-2226 and SMP-2240, which the registry omits. The seed must hold every sample those screens need, so no renumbering or single ordering can make one registry list match the design's curated subset. The same ceiling applies to the MaterialsList header counts. The honest options are to accept a measured, diagnosed mismatch on these registry boards, or to establish with the owner that the design's registry screens are illustrative subsets rather than exact fixtures.
