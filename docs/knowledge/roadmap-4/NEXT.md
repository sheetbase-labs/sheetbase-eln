## Order of work

   product owner. Nothing that waits on a decision starts before it is
   accepted; the tracker marks those tasks as waiting.
2. **Wave A — the product looks like v3**: DSYS-02..06, COMP-01..05,
   SHELL-01..05.
3. **Waves B–E** as in [`PROGRAMME_MAP.md`](PROGRAMME_MAP.md). Waves overlap;
   within a wave follow the dependency shape.

## Picking up work

1. `pnpm roadmap available` lists what is ready, highest priority first; the
   "Ready to start" list above is the same view. Skip anything whose
   "Waits on" task is not done.
2. `pnpm roadmap get <id>` shows the task; follow its **Spec** link to the
   stream file for the full goal, start-here files, steps and exit.
3. `pnpm roadmap update <id> --status in-progress` when you start, and the
   same for the step (subtask) you are on.
4. `pnpm roadmap note <id> "…"` for decisions, surprises and PR links as you
   go.
5. When a step's PR merges, mark the step done (tick it in
   [CHECKLIST.md](CHECKLIST.md) or `pnpm roadmap update <id> --status done`).
   The sync closes a task automatically when all its steps are done. If its
   exit criterion is not actually met, reopen it
   (`pnpm roadmap update <id> --status in-progress`) and add the missing step.
   Tasks without steps (the decisions) are closed by hand.
6. Run `pnpm roadmap:sync` and commit the `.nod/` changes, `CHECKLIST.md` and
   this file with your PR.

Full instructions: [GUIDE.md, section 9](GUIDE.md#9-tracking-work-with-nod).

## Maintenance rule

- The tracker in `.nod/` is the source of truth for status. `CHECKLIST.md`
  and the block above are generated from it; `pnpm test` fails when they are
  out of date (`tests/unit/roadmap-4-tracker.test.ts`).
- Every PR that advances a Roadmap 4 task updates the tracker in the same PR.
- The prose sections of this file change when the phase changes (for example
  when wave 0 is complete), with the date in `last_reviewed`.
- Adding, splitting or removing a task changes both its stream file in
  `tasks/` and the tracker (`pnpm roadmap create …`), in the same PR.
