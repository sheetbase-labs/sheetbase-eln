# UI port — sheetbase-app-3 into the ELN

**Status (2026-09-28):** active plan. Supersedes the vendored-HTML parity work.
Branch: `roadmap-4/ui-app3`. Decision: **A** — the ELN keeps the backend
(Postgres / PostgREST / RLS / RPCs); the UI from `../sheetbase-app-3` is ported
in, area by area, and wired to real data.

## Why

`sheetbase-app-3` is the new UI **already written** (TanStack Start, Tailwind v4,
Base UI, every canvas board a real route). Its data layer is fixtures behind
`createServerFn`. The ELN is the real product with the old UI. So the transition
is a **port**, not a design rebuild: copy app-3's components and routes, replace
fixture reads with real RPCs through `/api/db`, delete the old ELN UI as each
area lands.

app-3 is a **frozen reference**. Use its fixtures as the per-screen data
contract; do not ship them.

### Ordering constraint (learned porting Projects)

app-3 areas render their **own page header and toolbar** and assume app-3's
shell (top bar + nav + `_app` layout). ELN pages currently get their header from
`useShell()` via the old shell, so rendering an app-3 area inside the old shell
double-headers. Therefore the **shell must land before any area**, and an area
only later deletes its old ELN counterpart. The shell port means:

1. Vendor `shell/{app-shell,not-found}.tsx`, `shell/nav.ts`, `lib/theme.ts` into
   `v3/`, rewriting imports.
2. Wire `search-palette` to the ELN's real search (drop the fixture `search`
   server fn).
3. Render `AppShell` from `__root.tsx` (ELN keeps its flat route tree; app-3's
   `_app` grouping is not required) and feed it session/workspace/notification
   data from the ELN.
4. Retire ELN's `useShell()` page-header mechanism as each area supplies its own
   header; the two must not both render.

Consequence: the first deliverable is the **shell**, then Projects. Trying to port
an area first forces either a double header or a temporary adapter.

## Per-area definition of done

1. app-3 route + components are in the ELN, on the adopted shared layer.
2. Every read/write goes through the `/api/db` proxy or a session-preserving
   server function; **no fixtures**.
3. Every rule the screen shows is enforced by RPC/RLS with a DB test
   (success / denied / other-workspace / stale).
4. The area's app-3 tests (`tests/areas/*`, `tests/screens.mjs` URLs,
   `tests/interactions.mjs`) run against the ELN and pass.
5. The superseded ELN route/components/tests are deleted in the same change.

## First slice — Projects

Copy from app-3:

  `$projectId/{index,folders,members,settings}.tsx`
- `src/components/projects/{chip,mobile-list,options,project-inspector,refs,search-tabs,select}.tsx`

Wire to existing RPCs/data:

- list: `project_list_summary` (display id, client, stage, lead_name, status,
  experiment counts, archived_at)
- create: `create_project`; edit: `update_project_details` (revision)
- archive/unarchive: `archive_project` / `unarchive_project`
- members/access: `api.project_access` + workspace members
- folders: `api.folders`

Delete/replace on the ELN side: `src/routes/projects.tsx`,
`src/routes/projects/$projectId.tsx` (+ its test), `src/components/projects/project-list.tsx`.

Acceptance: `tests/areas/projects-inter.mjs` and the `/projects*` URLs in
`tests/screens.mjs` pass against the ELN dev server.

## Progress

- **Protocols area added**: `/protocols` lists protocol-template records (ID,
  protocol, status, owner, updated; tabs All/Active/In review/Drafts) and
  `/protocols/$protocolId` frames one with Document, Template and Used by tabs —
  the template reads the record's real notebook blocks, Used by reads
  `record_links`, and the controlled document, versions and training are stated
  as gaps. The nav lists Protocols, and the screens/areas suites cover the
  list and detail (43 routes × 2 widths clean).

- **Settings — instruments and parsers ported**: `/settings/instruments` lists
  the inbound instrument connectors and the registered parser catalogue
  (label + identity), links each instrument to its connector detail ("Test with
  a file") and adds instruments through the register-connector dialog. The
  parser catalogue renders after mount because the registry is module-level and
  can differ between the server and client bundles. Calibration has no model yet
  and is stated as a gap. Settings sections remaining: electronic signatures
  (needs a certification model).

- **Analysis view ported**: `/analysis/$analysisId` rebuilds a saved view from
  its stored ChartSpec through `resolveChartDataset` + `materialiseLiveChart`
  and renders it with the real chart renderer, with source/staleness
  diagnostics, the spec validity check and a link back to the studio. The studio
  at `/analysis` gains an Outlet so the child route renders inside app-3's shell
  (the studio still authoring). A malformed stored spec renders a diagnostics
  notice instead of crashing. The screens/areas suites discover a saved view
  when one exists.

- **Acceptance area/interaction suites ported**: `pnpm test:areas` runs the
  ported area suites (`tests/browser-scripts/areas/*.mjs` — datasets, inventory,
  pipelines, projects, settings) that discover real ids through `/api/db` and
  exercise the screens; `pnpm test:interactions` covers the shell (New menu,
  account appearance and its persistence, the search shortcut). All green. The
  API and SDK suite also exposed a real bug: the account menu's appearance
  switch changed only the local cache, so the server preference reverted it on
  reload; the switch now persists through `set_user_appearance`. A Base UI
  uncontrolled-`defaultValue` warning on the list search inputs was fixed by
  making them controlled.

- **Acceptance screens/phone ported**: `pnpm test:screens` loads every ported ELN
  route (static routes plus real ids discovered through `/api/db`) at desktop and
  phone widths and fails on a wrong status, a missing single visible h1,
  horizontal overflow or console/page errors; `--dark` runs the same in dark mode
  and `pnpm test:phone` is the phone-only pass. First runs: **42 routes × 2 widths
  = 0 problems**, dark 42 × 1 = 0 problems. The crawl now ignores the dev-auth-free
  Better Auth `list-sessions` 401, which is the only remaining crawl problem
