# UI port — sheetbase-app-3 into the ELN

**Status (2026-09-28):** active plan. Supersedes the vendored-HTML parity work.
Branch: `roadmap-4/ui-app3`. Decision: **A** — the ELN keeps the backend
(Postgres / PostgREST / RLS / RPCs); the UI from `../sheetbase-app-3` is ported
in, area by area, and wired to real data.

## Why

`sheetbase-app-3` is the new UI **already written** (TanStack Start, Tailwind v4,
Base UI, every canvas board a real route). Its data layer is fixtures behind
`createServerFn`. The ELN is the real product with the old UI. So the transition
is a **port**, not a design rebuild: copy app-3's components and routes, replace
fixture reads with real RPCs through `/api/db`, delete the old ELN UI as each
area lands.

app-3 is a **frozen reference**. Use its fixtures as the per-screen data
contract; do not ship them.

### Ordering constraint (learned porting Projects)

app-3 areas render their **own page header and toolbar** and assume app-3's
shell (top bar + nav + `_app` layout). ELN pages currently get their header from
`useShell()` via the old shell, so rendering an app-3 area inside the old shell
double-headers. Therefore the **shell must land before any area**, and an area
only later deletes its old ELN counterpart. The shell port means:

1. Vendor `shell/{app-shell,not-found}.tsx`, `shell/nav.ts`, `lib/theme.ts` into
   `v3/`, rewriting imports.
2. Wire `search-palette` to the ELN's real search (drop the fixture `search`
   server fn).
3. Render `AppShell` from `__root.tsx` (ELN keeps its flat route tree; app-3's
   `_app` grouping is not required) and feed it session/workspace/notification
   data from the ELN.
4. Retire ELN's `useShell()` page-header mechanism as each area supplies its own
   header; the two must not both render.

Consequence: the first deliverable is the **shell**, then Projects. Trying to port
an area first forces either a double header or a temporary adapter.

## Per-area definition of done

1. app-3 route + components are in the ELN, on the adopted shared layer.
2. Every read/write goes through the `/api/db` proxy or a session-preserving
   server function; **no fixtures**.
3. Every rule the screen shows is enforced by RPC/RLS with a DB test
   (success / denied / other-workspace / stale).
4. The area's app-3 tests (`tests/areas/*`, `tests/screens.mjs` URLs,
   `tests/interactions.mjs`) run against the ELN and pass.
5. The superseded ELN route/components/tests are deleted in the same change.

## First slice — Projects

Copy from app-3:

- `src/routes/_app/projects/index.tsx`, `$projectId.tsx`,
  `$projectId/{index,folders,members,settings}.tsx`
- `src/components/projects/{chip,mobile-list,options,project-inspector,refs,search-tabs,select}.tsx`

Wire to existing RPCs/data:

- list: `project_list_summary` (display id, client, stage, lead_name, status,
  experiment counts, archived_at)
- create: `create_project`; edit: `update_project_details` (revision)
- archive/unarchive: `archive_project` / `unarchive_project`
- members/access: `api.project_access` + workspace members
- folders: `api.folders`

Delete/replace on the ELN side: `src/routes/projects.tsx`,
`src/routes/projects/$projectId.tsx` (+ its test), `src/components/projects/project-list.tsx`.

Acceptance: `tests/areas/projects-inter.mjs` and the `/projects*` URLs in
`tests/screens.mjs` pass against the ELN dev server.

## Progress

- **Experiments list ported**: `/experiments` renders app-3's list (tabs
  All/Mine/In progress/In review/Approved/Drafts, filter to last 30 days, sort,
  table + mobile) on real experiment records; rows open the record. Protocol
  version, open issues and started date are design fields the model lacks and
  render as gaps. The nav now lists Experiments; the dedicated
  `/experiments/$expId` frame follows.

- **Sample detail ported**: `/samples/$sampleId` is app-3's frame (crumbs,
  status/type meta, Withdraw/Move actions, tabs Details/Usage/History/Lineage/
  Measurements) on real sample records; Withdraw/Move use `consume_sample` /
  `transfer_sample`; Usage reads `record_links`; History reads `sample_events`.
  Lineage and Measurements state their unbuilt capabilities rather than faking
  a tree. The list's name links into the detail.

- **Materials list ported**: `/materials` (renamed from `/reagents`) renders
  app-3's materials registry (tabs In stock/Expiring/Quarantine/Expired, search,
  table + mobile list, footer, lot inspector) wired to real reagent records
  (`fetchReagentsPage` + `reagentAttention`); Receive lot writes through
  `record_reagent_movement`. `reagentPath`, nav and the legacy shell point at
  `/materials`; the old reagents page is deleted.

- **Samples list ported**: `/samples` renders app-3's registry list (header,
  tabs In stock/Mine/Awaiting/Quarantine/Consumed, search toolbar, table,
  mobile list, footer, summary inspector) wired to real sample records through
  `fetchSamplesPage`, plus Register sample through `create_model_record`. The
  old samples page and its tests are deleted. The sample detail route and
  custody dialogs follow.

- **Search ported**: `/search` renders app-3's results page (filter aside, type
  facets, updated/archived filters, grouped results) wired to the real `search`
  RPC and `search_did_you_mean` for "Did you mean". The old Search page and its
  test are deleted. Gaps: multi-type filtering is client-side over the top 100
  results; the ⌘K palette is still the ELN's own (app-3's palette lands next).

- **Schedule ported**: `/schedule` renders app-3's day/week instrument grid and
  phone day list, wired to `calendar_resources` (instruments) and
  `calendar_bookings`; "Book instrument" writes through `create_booking`. The
  old `/calendar` route and its test are deleted; nav and Home point at
  `/schedule`. Gaps: the wire has no booking creator, so `mine`/who styling is
  omitted; the "Materials for today" section waits on the materials capability.

- **Inbox ported**: `/inbox` renders app-3's list with Needs action / Following
  / Done today tabs, type filters and a details panel, wired to `my_work_items`
  (`useWorkItems` + `groupWorkItems`). Data-issue, signature and material kinds
  arrive with their capabilities; the old Inbox and its test are deleted.

- **Home ported**: `/` renders app-3's Home wired to the real work items
  (reviews awaiting you), today's calendar bookings and active dataset flags.
  The old 1988-line Home and its test are deleted; the root chrome switch now
  includes `/`.

- Foundations staged under `src/components/v3/`: UI kit, icons, shared types,
  Projects pieces, shell + nav + theme, token-name bridge, `@base-ui/react`.
- Root chrome switch: `__root.tsx` renders app-3's `AppShell` for routes listed
  in `v3RouteIds` and the ELN shell for everything else, so areas can be ported
  without regressing unported screens. The list shrinks as areas move; at the
  end the branch and the ELN shell are deleted.
- **Projects list ported**: `/projects` renders app-3's screen wired to
  `project_list_summary` + `create_project`, inside app-3's shell. The ELN's
  `projects.tsx` list, `components/projects/project-list.tsx`, its story and the
  old list tests are deleted. Known gaps (design data the backend does not carry

  client (code → id) and stage, not lead (needs a member-name list).
- **Project detail ported**: `/projects/$projectId` is app-3's frame (crumbs,

  Old detail page and its test deleted.
- **Members tab ported** with a DB-first capability: `api.workspace_members_list`,
  `api.project_members` (names + access + lead), and `api.set_project_member` /
  `api.remove_project_member` gated to the project lead or a workspace admin.
  DB tests cover read, add/change/remove, denial and an invalid access level.

  `api.create_project_folder` and `api.move_records_to_folder`, gated to project
  editors (lead, workspace admin or an editor/owner `project_access`). DB tests
  cover create/move, viewer denial, invalid name and cross-project parent.
- Still open for the area: the design fields the backend lacks (milestones,
  member summary, started date) and per-project roles beyond the access level.
