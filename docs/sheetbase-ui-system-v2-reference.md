## Status rules

Status below is copied from `design-system/registry.ts`; **unregistered** means the
registry makes no `draft`/`beta`/`stable` claim. It should not be interpreted as
draft. The registry contains only Button, Badge, Input, Select, Dialog, Sheet,
Table, Command, StatusBadge, NotebookBlock, PlateMap, and ApprovalStepper (plus
the draft Record document and Registry templates).

All primitives accept `className` unless noted. “Radix props” means the component
passes through the props of the named Radix primitive; ordinary wrappers pass
through the indicated React HTML attributes.

## Showcase helpers

`components/showcase.tsx` is not in the registry and exports four documentation
layout helpers:

- **PageHeader** — `{ eyebrow?: string; title: string; description: string;
children?: ReactNode }`. Responsive bordered flex header; primary uppercase 11px
  eyebrow, `font-display text-2xl` title, muted body copy.
- **ShowcaseSection** — `{ id: string; title: string; description?: string;
children: ReactNode; className?: string }`. Scroll offset, bottom border, `py-8`,
  `font-display text-lg` title and muted description.
- **Preview** — `{ title: string; description?: string; children: ReactNode;
className?: string; status?: 'stable'|'draft' }`. Card-like bordered preview with
  muted/25 header; status maps to success/warning Badge. Note that it cannot show
  registry `beta`.
- **TokenSwatch** — `{ name: string; value: string; colour: string }`. Uses
  `colour` as inline `background`; bordered card, 20-unit swatch, compact label and
  muted code value.

## Registry inventory

The complete registry has eight stable UI entries (Button, Badge, Input, Select,
Dialog, Sheet, Table, Command), one stable scientific entry (StatusBadge), three
beta scientific entries (NotebookBlock, PlateMap, ApprovalStepper), and two draft
template entries: **Record document** and **Registry**, both sourced from
`routes/templates.tsx`. No other reference source file receives a lifecycle status.

## Actual-app coverage comparison

Comparison is based on actual source files, not only exports.

### UI files absent from `src/components/ui/`

`accordion`, `avatar`, `breadcrumb`, `button-group`, `calendar`, `empty`,
`hover-card`, `kbd`, `pagination`, `popover`, `progress`, `radio-group`,
`scroll-area`, `slider`, `sonner`, `spinner`, `switch`, `toggle`, and
`toggle-group` are absent. This exactly matches the additional reference UI set
listed in the request. The 20 named actual-app UI primitives are present.

### Scientific reference files vs actual app

None of the eleven reference files exists at the same
`src/components/sheetbase/<name>.tsx` path because the actual app has no
`src/components/sheetbase/` directory. However, several have clear actual-app
counterparts under domain folders:

- `approval-stepper` → `src/components/audit/approval-stepper.tsx`
- `audit-trail` → `src/components/audit/audit-trail.tsx`
- `chart-frame` → `src/components/viz/chart-frame.tsx`
- `notebook-block` → `src/components/notebook/notebook-block.tsx`
- `plate-map` → `src/components/viz/plate-map.tsx`
- `record-link` → `src/components/scientific/record-link.tsx`
- `status-badge` → `src/components/scientific/status-badge.tsx`

No same-name actual-app source file was found for **SampleDataTable**
(`data-table.tsx`), **MetricCard**, **PropertyList/Property**, or **SampleChart**.
There are domain-specific table/chart/metric-like implementations elsewhere, but
they are not direct same-name implementations of these reference APIs.
